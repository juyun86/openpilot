# 高速／高架变道统一修复（2026-09-22，本地候选）

本轮按统一审查的 LC-11～15、LC-18 实施，限定五个既有运行模块，未改方向盘控制、模型轨迹、纵向控制器、车端参数或生产目录。继续遵守最小侵入、复用系统能力、司机接管优先及原有控制资格。城市路口能力不作为本阶段交付条件，原有城市分支未被顺带删除。

## 修复结果

| 问题 | 最终行为 |
| --- | --- |
| LC-11 同包危险覆盖 | 同时间戳 399 报文中的逐侧危险取保持关系，后续同包正帧不能清掉危险；新的有效观测可以恢复。坏 DLC／校验后的同包帧不能重建有效性，需后续新样本。OR 正许可与原有独立危险否决保持。 |
| LC-12 执行异常后重试 | 已进入 changing 的异常退出保存该事件“完成未确认”终态。首次保留原始故障原因，恢复后仍锁止，不因邻道重新稳定、零事件或 revision 改变再次请求。执行前的正常观察恢复不被一并锁死。 |
| LC-13 效率取消换编号 | 明确取消及已开始动作的健康／司机介入／路线变化出口锁住本导航 session；不通过失败冷却后的新合成事件绕过。有效新 session 可重新准入。 |
| LC-14 出口准入过晚 | 高速／快速路 exit、ramp、merge、keep、slight 分支在原准入函数中检查当前速度与剩余距离，至少保留原协调器 10 s 执行上限对应的距离；速度未知／非有限或非正不准入。90 km/h 时距离必须大于 250 m，120 km/h 时大于约 333 m。每次更新重查，但已开始动作仍由原协调器与模型执行，不据此强制回原道或急刹。 |
| LC-15 灯光取消失败 | 取消已请求但结果不是确认成功时，原灯光 controller 保存失败锁，拒绝后续软件灯光请求，包括更换编号／方向及验证请求。锁在 controller 重新初始化时清除，不通过时间、上游请求重现或参数轮询自动解除。驾驶员实体转向灯操作未改。 |
| LC-18 旧测试预期 | 相对周期的灯光集成测试改为期待 CompletionUnconfirmed，保留原有实体灯光释放时机断言。 |

出口预算复用的是既有软件执行上限，不是新标定的实际变道完成时间；它解决临近出口仍新启动的问题，不证明所有几何、交通及分叉场景都已具备足够距离。灯光失败锁采用明确的控制器生命周期边界，本轮没有自动重新初始化或重启车机。
